# design-sync notes — @balena/ui-shared-components

## Re-sync risks
- **The final full render check never exited 0 on this machine** — user explicitly signed off on closing out with: sampled validates exit 0, all 34 components graded `match` against storybook per-story, and the failing components rotating run-to-run with screenshots containing the rendered content (validator races React 18's async mount after `networkidle`; see the harness-bug bullet below). A future sync on a faster/quieter machine should get a clean full pass; if it doesn't, it's this same race, not the components.
- The `.ds-sync/` staged-scripts patches (http-serve.mjs SVG MIME) wash away every re-staging — re-apply before compare runs, or reference-side images with svg/jpg/webp sources grade falsely as mismatch.
- The `theme` object and `Material.*` namespaces ship whole-vendor (MUI 7.3.x) — a MUI major bump upstream changes both sides of every compare; expect broad recaptures then.
- Callout was graded at `--max-stories 7` (all stories); every other multi-story component used the default 6-story cap — tail stories beyond the cap are verified-by-upload, not image-graded.
- Alert/Autocomplete (docs stories for raw MUI) and SimpleConfirmationDialog (not a public export) are deliberately excluded via titleMap nulls — if balena later exports SimpleConfirmationDialog, remove its null and re-sync.
- Overlay components verify in their CLOSED state (that's what their stories render in storybook too) — the open-overlay renders are NOT covered by any grade.
- Fonts load from Google Fonts at runtime (remote @import) — an offline/blocked-egress consumer of the project renders fallback fonts; nothing ships locally to change that.

- [GENERAL] `.design-sync/overrides/dts.mjs` fork: RJST is a real storied component whose ALL-CAPS name trips the stock `isComponentName` enum/constant rejection, silently dropping it from the build (`[ZERO_MATCH]` on compare, absent from .stories-map.json). The fork exempts RJST by name. Any future all-caps component hits the same filter — extend `ALL_CAPS_COMPONENT_EXEMPT` in the fork. The fork imports `ts-morph`, so it needs the gitignored symlink `.design-sync/node_modules -> ../.ds-sync/node_modules` (recreate per clone: `ln -sfn ../.ds-sync/node_modules .design-sync/node_modules`).
- The compare capture flake signature: a component whose EVERY story reports `unpaired`/empty with an intact generated wrapper is the machine-load flake, not a pairing bug — re-run a scoped `compare.mjs --components <Name>` (solo for large story modules like DownloadImageDialog) before diagnosing. Flake probability scales with story-module size and concurrent captures.
- Overlay components (Tooltip, CookiesBanner, TagManagementDialog, DownloadImageDialog, SurroundingOverlay, DialogWithCloseButton) all keep their overlay CLOSED by default behind a story-local trigger, and storybook shows the same closed state — previews match without cardMode/skip overrides; no [PORTAL?] fired anywhere.
- Copy's Default story renders near-blank on BOTH panels by design (hover-revealed icon, no children) — not [RENDER_BLANK]. Markdown/RJSForm ds captures clip at the capture viewport height (content below the fold verified identical) — framing artifact.

## Known render warns
- `[RENDER_THIN] Img: variants render identically` — legitimate: the Fallback story intentionally renders the same logo (broken src + logo fallback), so both cells look identical.

- [GENERAL] package.json had no `types` field (only `main: ./dist/index.js`), so the converter's `.d.ts` export discovery found 0 exports (`exported PascalCase symbols: 0`, cascading into `[TITLE_UNMAPPED]` for every component). Fix: added `"types": "./dist/index.d.ts"` to package.json — a standard packaging improvement, keep it.
- Storybook decorators (`.storybook/preview.tsx`): MUI `ThemeProvider` with `theme` from `src/theme` + `ScopedCssBaseline` + `AnalyticsContextProvider`. The converter auto-bundles these as preview-decorators.js.
- Tokens come from `@balena/design-tokens` (auto-detected `[TOKENS_PKG]`); its CSS lives at `build/css/tokens.css` inside the package.
- Reference storybook: `npx storybook build -c .storybook -o .design-sync/sb-reference` from repo root (storybook 10, react-webpack5).
- Converter invocation: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules ./node_modules --entry ./dist/index.js --out ./ds-bundle`.
- `tokensGlob: "build/css/*.css"` — @balena/design-tokens keeps its CSS at `build/css/tokens.css`, not the default `dist/css|css|dist` locations.
- `cssEntry: ".storybook/global.css"` — small global stylesheet (box-sizing, body font via tokens, link color) copied from the balena Dashboard; component styles are emotion (CSS-in-JS, runtime) so there is no compiled component stylesheet by design.
- titleMap exclusions: `Alert`/`Autocomplete` are docs stories for themed MUI components — the package re-exports MUI only under the `Material` namespace, and titleMap can't target a namespace member, so they're excluded from the sync. `SimpleConfirmationDialog` has stories but is NOT a public export of the package (nothing to ship); excluded.
- titleMap fixes: story title "Other/Collection summary" → `CollectionSummary`; "Other/RJS Table" → `RJST`.
- Fonts: Source Sans Pro + Ubuntu Mono load from Google Fonts via a remote stylesheet `@import` in styles.css (harvested from .storybook/preview-head.html) — nothing to ship locally.
- [GENERAL] `cfg.provider` is set explicitly (AnalyticsContextProvider → Material.ThemeProvider(theme via $ref) → Material.ScopedCssBaseline) because the auto-bundled `.storybook/preview.tsx` decorators crash: preview.tsx imports `balenaTheme` from `./manager`, which calls `create()` from storybook's `theming` module — the converter's inert stub doesn't expose `create` through CJS→ESM interop (`(0, import_theming.create) is not a function` in every cell). The explicit chain mirrors the decorators exactly (storybook applies `decorators: [A, B]` as B(A(story)), so AnalyticsContextProvider is outermost).
- [GENERAL] `extraEntries: ["react-router-dom"]` — RouterLinkWithTracking's story wraps in `BrowserRouter` imported from react-router-dom; without the extraEntry the story bundles a FRESH react-router-dom copy whose Router context differs from the copy inlined in _ds_bundle.js, and the component's inner Link throws "Cannot destructure property 'basename' of useContext(...) as it is null". extraEntries merges react-router-dom onto the window global so story imports shim to the same instance.
- [GENERAL] `.design-sync/overrides/story-imports.mjs` fork: stories import `@mui/material` (Button, Box, Typography, …) and `@tanstack/react-query` directly for their scaffolding. Without the fork each preview bundles a FRESH MUI copy — story-local MUI elements lose the provider's theme (e.g. DialogWithCloseButton's "Open modal" trigger rendered as a default MUI text button instead of the balena pill button) and previews gain ~300KB each. The fork maps those specifiers onto the global's existing namespace re-exports (`Material`, `ReactQuery`, …). Do NOT instead add `@mui/material` to extraEntries: ESM star-merge silently drops collision names (react-router-dom's `Link` vs MUI's `Link`, and SettingsCard's story needs the MUI one).
- [GENERAL] Harness bug (re-apply after every script re-staging until fixed upstream): `.ds-sync/storybook/http-serve.mjs` MIME table lacks `.svg` (and jpg/gif/webp/woff2) — SVGs serve as `application/octet-stream`, browsers refuse them in `<img>`, and the REFERENCE side of every svg-using story (Img, LimitedRowImages, avatars from `public/`) captures a broken-image glyph while the preview renders fine. Patch: add `'.svg': 'image/svg+xml'` etc. to the MIME map. Worth reporting to the design-sync skill maintainers.
- The §3 channel-open gate was passed with `--render-sample 10` (exit 0) because sustained machine load (QEMU VM) made the full 33-preview render check flake nondeterministically; the FULL render check must still pass at the final upload gate.
- The validator's render check is flaky under machine load (networkidle fires before React 18's async commit): random components report "root empty" with no error, different set each run, and pass on re-run. Confirmed by probing the same pages directly (they render fine, content mounts immediately at networkidle when the machine is idle). If validate fails with a random-looking `[RENDER]` set, re-run it when the machine is quieter before chasing component bugs. RouterLinkWithTracking was the only CONSISTENT failure (real bug, fixed via extraEntries).
